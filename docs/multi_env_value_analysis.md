# 多 Env 在 SpaceMouse 接管训练中的价值分析

## 背景

当前训练配置：8 个并行 env，其中 env_0 支持 SpaceMouse 人工接管，env_1-7 完全由策略控制。

问题：其他 env 存在的意义大不大？和只用一个 env_0 并在需要时接管，差别大吗？

## 结论

**其他 7 个 env 非常有价值，差别很大。**

## 分析

### 1. 数据量和采样效率

|  | 只用 env_0 (1 env) | 8 envs (当前) |
|---|---|---|
| 每个 rollout epoch 采集的 step | 100 | 100 × 8 = 800 |
| 填满 replay buffer 速度 | 慢 8 倍 | 正常 |

SAC 是 off-policy 算法，核心优势是从大量历史经验中反复学习。env_1-7 产生的数据虽然训练初期质量不高（策略还没学好），但提供了：

- **状态空间覆盖**：策略的随机探索会到达各种不同的状态，帮助 Q 网络建立准确的 Q 值地图
- **负样本信号**：env_1-7 的失败轨迹是"什么不该做"的重要信号。没有这些负样本，Q 网络会对未探索区域的 Q 值估计不准（通常偏高），导致策略盲目往那些区域走

### 2. RLPD 对称采样的意义

当前训练使用 RLPD（Reinforcement Learning with Prior Data），每个 training batch 由两部分组成：

- **50%** 来自 replay buffer（包含 env_0-7 的所有在线数据）
- **50%** 来自 demo buffer（来自离线示范 + SpaceMouse 接管轨迹）

只有 1 个 env 时：
- replay buffer 几乎只有接管数据和少量策略数据
- demo buffer 和 replay buffer 的数据高度重叠
- 失去对称采样的多样性优势

有 8 个 env 时：
- replay buffer 有大量多样的策略探索数据
- demo buffer 有高质量的接管数据
- 两者形成互补：demo 教策略"该做什么"，replay 教 Q 网络"整个状态空间长什么样"

### 3. Q 值估计的准确性

SAC 的 actor loss 是 maximize Q(s, π(s))——策略朝着 Q 值最高的方向优化。Q 值估计是否准确直接决定策略能否学好。

- **只有 env_0 的数据**：Q 网络只见过"接管时的好动作"和"接管间歇期策略的少量动作"。对于大量未见过的 state-action 区域，Q 值是外推得到的，通常不准确。策略可能跑到一个 Q 网络"以为很好但其实很差"的区域
- **有 env_1-7 的数据**：策略在 7 个 env 中的随机探索会覆盖大量 state-action 对，Q 网络对整个空间的估计更准确。这就是 off-policy RL 中 exploration 的核心价值

### 4. 类比理解

你是一个老师（SpaceMouse），在教 8 个学生（env）。你只能手把手辅导 1 个学生（env_0），但另外 7 个学生在旁边自己练习。

- **只有 1 个学生的情况**：你手把手教的时候他学了，但你一放手他就不知道该怎么应对没见过的情况（因为他只见过你引导的情境）
- **8 个学生的情况**：7 个学生自己练习，虽然经常犯错，但他们的错误经验是共享的。所有学生（包括你辅导的 env_0）共用同一个"大脑"（policy network），所以 env_1-7 犯的错帮助整个策略知道了"什么是不好的"，而你的示范帮助策略知道"什么是好的"

### 5. 计算开销几乎不变

8 个 env 是并行运行的（在同一个 GPU 上 batch simulation），增加 env 数量几乎不增加 wall-clock time，但数据量线性增长。几乎是"免费"的数据增益。

## 总结对比

| 维度 | 1 env + 接管 | 8 envs + 接管 env_0 |
|------|-------------|---------------------|
| 数据多样性 | 低 | 高（7x 额外探索） |
| Q 值准确性 | 差（大量外推） | 好（覆盖广） |
| RLPD 效果 | 弱（数据重叠） | 强（互补） |
| 策略泛化性 | 差（只见过接管附近的状态） | 好（见过各种失败/探索状态） |
| 计算开销 | 1x | ≈1x（并行 sim） |
